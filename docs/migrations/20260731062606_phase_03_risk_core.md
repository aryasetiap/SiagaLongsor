# Phase 03 risk core

Migration `20260731062606_phase_03_risk_core` menambahkan fondasi penyimpanan risk engine tanpa
mengubah data Phase 01–02:

- `RiskProfile` menyimpan konfigurasi Site yang versioned dan immutable.
- `RiskAssessment` menyimpan satu hasil evaluasi immutable per telemetry.
- `CurrentMonitoringPointState` menyimpan projection current state dan counter hysteresis.
- enum `RiskLevel`, `ConnectivityStatus`, dan `CalibrationStatus`.

## Constraint dan SQL manual

- `(siteId, version)` unik dan partial unique index memastikan hanya satu profile aktif per Site.
- Trigger PostgreSQL menolak perubahan version/configuration serta reaktivasi. Satu-satunya update
  yang diizinkan adalah deactivation satu arah ketika version baru dibuat dalam transaction yang
  sama.
- `RiskAssessment.telemetryId` unik, foreign key bersifat `RESTRICT`, dan reasons wajib JSON array.
- Projection memiliki satu row per MonitoringPoint, latest telemetry unik, pasangan profile
  konsisten, serta counter non-negatif.

Partial index dan trigger ditulis dengan SQL migration karena keduanya tidak dapat diekspresikan
lengkap dalam Prisma schema.

## Compatibility dan inisialisasi

Migration bersifat additive. Existing Site belum otomatis memperoleh profile; seed development
membuat version 1 provisional hanya bila version tersebut belum ada. Current projection juga tidak
di-backfill: row pertama dibuat ketika Site yang memiliki active profile menerima current
telemetry baru. Exact duplicate dan late telemetry tidak memajukan projection.

Threshold seed bersifat provisional dan bukan threshold bencana final. Kalibrasi ahli serta data
lapangan tetap wajib.

## Verifikasi dan recovery

Verifikasi dengan database kosong menggunakan `prisma migrate deploy`, seed dua kali, lalu
`prisma migrate status`. Uji juga bahwa update konfigurasi version lama dan active profile kedua
pada Site yang sama ditolak.

Rollback otomatis tidak disediakan karena assessment dan profile merupakan audit history. Bila
deployment gagal sebelum menerima data Phase 03, recovery yang aman adalah memulihkan backup,
memperbaiki migration pada branch yang belum dirilis, dan mengulang deploy. Setelah data Phase 03
ada, jangan drop tabel; lakukan forward-fix migration.
